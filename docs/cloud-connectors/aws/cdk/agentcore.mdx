`OdigosAgentCoreInstrumentation` writes the Odigos environment recipe onto Amazon Bedrock AgentCore runtimes
defined in your CDK app. It is the CDK form of
[self-managed AgentCore instrumentation](/cloud-connectors/aws/workloads/agentcore/instrument#self-managed-instrumentation).

<Note>
  Read [Odigos AWS CDK](/cloud-connectors/aws/cdk/overview) first. It covers
  installing the package and how Odigos recognizes an instrumented workload. Then read
  [Destinations](/cloud-connectors/aws/cdk/destinations) for the shared `destination`
  options. This page covers only what's specific to AgentCore.
</Note>

## Basic usage

```typescript
import {
  OdigosAgentCoreDistribution,
  OdigosAgentCoreInstrumentation,
  OdigosAgentCoreLanguage,
  OdigosAgentCoreSdk,
} from '@odigos/aws-cdk';

const odigos = new OdigosAgentCoreInstrumentation(this, 'Odigos', {
  destination: { httpEndpoint: 'https://otlp.example.com:4318' },
});

odigos.instrument({
  runtime: agentRuntime,                           // CfnRuntime, the L2 Runtime, or a CfnInclude resource
  language: OdigosAgentCoreLanguage.PYTHON,        // stated, not detected
  distribution: OdigosAgentCoreDistribution.ADOT,  // the profile prepared into the artifact
  sdk: OdigosAgentCoreSdk.ODIGOS,                  // or ADOT for an artifact carrying ADOT only
});
```

```python
from odigos_aws_cdk import (
    OdigosAgentCoreDistribution,
    OdigosAgentCoreInstrumentation,
    OdigosAgentCoreLanguage,
    OdigosAgentCoreSdk,
)

odigos = OdigosAgentCoreInstrumentation(self, "Odigos",
    destination={"http_endpoint": "https://otlp.example.com:4318"},
)
odigos.instrument(
    runtime=agent_runtime,
    language=OdigosAgentCoreLanguage.PYTHON,
    distribution=OdigosAgentCoreDistribution.ADOT,
    sdk=OdigosAgentCoreSdk.ODIGOS,
)
```

Create the construct once, then call `instrument()` for each runtime, or pass them as `targets`. Instrumenting
the same runtime twice is a no-op, and a second construct cannot instrument a runtime the first one owns.

## How it works

The construct writes property overrides on the runtime's `EnvironmentVariables`: the export settings, the SDK
selection, the `ODIGOS_AGENTCORE_PACKAGE` preparation contract and the `ODIGOS_IAC` marker. It removes the
per-signal header variables, `ODIGOS_MANAGED` and, when the destination has no headers,
`OTEL_EXPORTER_OTLP_HEADERS`. Other variables the runtime sets are kept. Because it uses property overrides, it
works with any `aws-cdk-lib` version that can define the runtime.

<Warning>
  The construct does not prepare the artifact. The SDK must already be in the image or
  ZIP the runtime deploys; environment variables alone install nothing, and Odigos then
  reports the runtime as not conformant or sends no telemetry. See
  [Prepare an AgentCore artifact](/cloud-connectors/aws/workloads/agentcore/prepare).
</Warning>

Odigos validates the runtime and never changes it. Leave AgentCore sources self-managed in Odigos: the connector
refuses to take over a runtime that carries `ODIGOS_IAC`.

## Choosing the route

<ParamField path="sdk" type="OdigosAgentCoreSdk" default="ODIGOS">
  Which SDK the artifact carries. It must match how you built it: the connector reads it back from
  `ODIGOS_AGENTCORE_PACKAGE` and compares the runtime against that route's recipe. The earlier `delivery` option
  (`PACKAGE`, `ADOPT`) still works and is deprecated.
</ParamField>

| | `ODIGOS` (default) | `ADOT` |
| --- | --- | --- |
| The artifact carries | The Odigos package (`odigos-agentcore[adot]` or `[openllmetry]`, `@odigos/agentcore`) or the carrier bundle | AWS Distro for OpenTelemetry only |
| SDK start | The package's bootstrap, switched on by `ODIGOS_AGENTCORE_ENABLED` | ADOT's own launcher, which you set up |
| Distributions | `ADOT` or `OPENLLMETRY` | `ADOT` only; any other throws at synth |
| AgentCore service span | Linked: the bootstrap roots each invocation at the agent | Missing: ADOT cannot root the invocation |
| Content redaction | Applied by the bootstrap | Only the capture switches |

For `ADOT`, prepare the artifact like this:

- **Python:** add `aws-opentelemetry-distro` and start through `opentelemetry-instrument`. A ZIP's entry point
  becomes `["opentelemetry-instrument", "app.py"]`; an image's `CMD` must start through `opentelemetry-instrument`, set in its Dockerfile.
- **Node.js (CommonJS):** add `@aws/aws-distro-opentelemetry-node-autoinstrumentation` and append
  `--require @aws/aws-distro-opentelemetry-node-autoinstrumentation/register` to `NODE_OPTIONS`, on the runtime
  or in the image, keeping existing flags. The construct does not write `NODE_OPTIONS`.

## Naming the entry point script

<ParamField path="entryPointScript" type="string">
  Direct-code ZIP on sdk `ODIGOS` only: your script, relative to the ZIP root. The construct writes it to
  `ODIGOS_AGENTCORE_ENTRYPOINT`; set the runtime's `EntryPoint` to the start wrapper alone. Setting it with sdk
  `ADOT` throws at synth.
</ParamField>

AgentCore accepts a second entry point element only after `opentelemetry-instrument`, so the runtime's
`EntryPoint` is `["odigos_agentcore_start.py"]` (Python) or
`["node_modules/@odigos/agentcore/odigos_agentcore_start.js"]` (Node.js), and the wrapper reads your script from
`ODIGOS_AGENTCORE_ENTRYPOINT`. Leave `entryPointScript` unset for container images.

## Stating the language and distribution

<ParamField path="language" type="OdigosAgentCoreLanguage" required>
  `PYTHON` (3.12) or `NODEJS` (22, CommonJS). Native ESM Node.js is not covered.
</ParamField>

<ParamField path="distribution" type="OdigosAgentCoreDistribution" default="ADOT">
  The profile prepared into the artifact: `ADOT` or `OPENLLMETRY`. The construct cannot see the artifact, so a
  mismatch is reported by Odigos as non-conformance rather than caught at synth.
</ParamField>

## Naming the service

<ParamField path="serviceName" type="string">
  `OTEL_SERVICE_NAME` for the runtime. Defaults to the runtime's `AgentRuntimeName`, and is required when that
  is not a literal string.
</ParamField>

<Warning>
  The service name must match the workload's name in Odigos: the runtime name, unless a
  service name override is configured for the source. A different value is reported as drift.
</Warning>

## What it writes

With `sdk: ODIGOS`, for a Python runtime using the ADOT distribution:

| Variable | Value |
| --- | --- |
| `ODIGOS_IAC` | `{"distro":"python-agentcore-adot","recipe":"1","v":1}` |
| `ODIGOS_AGENTCORE_PACKAGE` | `{"v":1,"language":"python","distros":["python-agentcore-adot"]}`; Node.js adds `"moduleFormat":"commonjs"` |
| `ODIGOS_AGENTCORE_ENABLED`, `ODIGOS_AGENTCORE_DISTRO` | `true`, `python-agentcore-adot` |
| `ODIGOS_AGENTCORE_ENTRYPOINT` | your `entryPointScript`; written only when it is set |
| `OTEL_PROPAGATORS` | `tracecontext,baggage,xray` |
| `OTEL_SERVICE_NAME` | see above |
| `OTEL_EXPORTER_OTLP_*`, `OTEL_*_EXPORTER` | the destination's base URL, per-signal endpoints and exporters |
| `OTEL_EXPORTER_OTLP_HEADERS` | the destination headers, URL-encoded and sorted; removed when there are none |
| `DISABLE_ADOT_OBSERVABILITY`, `AGENT_OBSERVABILITY_ENABLED` | `true`, `false` |
| `OTEL_PYTHON_*` (Python) | the distribution's distro, configurator and disabled instrumentations |

With `sdk: ADOT` it writes the connector's ADOT recipe instead, the same environment Odigos-managed
instrumentation applies when it starts ADOT:

- `ODIGOS_AGENTCORE_ENABLED`, `ODIGOS_AGENTCORE_DISTRO` and `ODIGOS_AGENTCORE_ENTRYPOINT` are removed.
- `OTEL_PROPAGATORS` is `tracecontext,baggage`.
- `ODIGOS_AGENTCORE_PACKAGE` declares ADOT:
  `{"v":1,"language":"python","distros":["python-agentcore-adot"],"mode":"adopt"}` for Python,
  `{"v":1,"language":"nodejs","distros":["nodejs-agentcore-adot"],"moduleFormat":"commonjs","mode":"adopt"}` for
  Node.js.

Every key is compared exactly by Odigos, so the construct warns at synth when the runtime already sets one of
them to a different value, when the total would exceed AgentCore's 50 variables, or when the environment is
over the platform's size limit (1536 bytes for V2 code artifacts, 2560 for V2 containers).

## Destination

AgentCore exports directly to a global OTLP/HTTP destination. `httpEndpoint` is required, as an `http` or
`https` base URL without credentials, query, fragment or a per-signal `/v1/...` path; a gRPC `endpoint` is
rejected. `destination.headers` is written into `OTEL_EXPORTER_OTLP_HEADERS` as plain runtime configuration,
readable by anyone with `bedrock-agentcore:GetAgentRuntime`.

## API reference

| Export | What it is |
| --- | --- |
| `OdigosAgentCoreInstrumentation` | The construct. Method: `instrument(target)`. |
| `OdigosAgentCoreTarget` | One runtime to instrument: `runtime`, `language`, `distribution`, `sdk` (`delivery` is its deprecated alias), `entryPointScript`, `serviceName`. |
| `OdigosAgentCoreLanguage` | `PYTHON` \| `NODEJS` |
| `OdigosAgentCoreDistribution` | `ADOT` \| `OPENLLMETRY` |
| `OdigosAgentCoreSdk` | `ODIGOS` \| `ADOT` |
| `OdigosAgentCoreDelivery` | Deprecated alias of `OdigosAgentCoreSdk`: `PACKAGE` \| `ADOPT` |
| `AGENTCORE_AGENTS_IMAGE` | The carrier image this package version pairs with, for preparing an artifact without registry access. |
