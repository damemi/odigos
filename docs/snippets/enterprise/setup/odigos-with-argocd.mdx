This guide shows you how to deploy Odigos in your Kubernetes cluster using Argo CD with the official Odigos Helm chart. This allows for GitOps-based management and observability instrumentation across your applications.

## Prerequisites

Before you begin, make sure you have:

* A running Kubernetes cluster
* Argo CD installed and configured in the cluster
* Helm CLI installed (optional but useful for inspection and verification)

## Step 1: Give Argo CD Access to the Odigos Registry

The Odigos Helm chart is hosted as an OCI artifact on the private registry `registry.odigos.io`. Create an Argo CD repository secret so Argo CD can pull it. The username is always `odigos`; the password is your on-prem token:

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: odigos-helm-registry
  namespace: <ARGOCD_NAMESPACE>  # <- Replace with your Argo CD namespace
  labels:
    argocd.argoproj.io/secret-type: repository
stringData:
  type: helm
  name: odigos
  url: registry.odigos.io/charts
  enableOCI: "true"
  username: odigos
  password: <TOKEN>
```

```bash
kubectl apply -f odigos-helm-registry.yaml
```

## Step 2: Identify the Helm Chart Version

Choose the chart version to use as `targetRevision`, without a leading `v` (for example `1.40.0`). To see the latest version, log in with Helm and show the chart:

```bash
echo "$ODIGOS_TOKEN" | helm registry login registry.odigos.io -u odigos --password-stdin
helm show chart oci://registry.odigos.io/charts/odigos | grep '^version:'
```

## Step 3: Define the Argo CD Application Manifest

Create an Argo CD `Application` custom resource to deploy Odigos using Helm. Save the following YAML as `odigos-application.yaml`:

```yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: odigos
  namespace: <ARGOCD_NAMESPACE>  # <- Replace with your Argo CD namespace
  finalizers:
  - resources-finalizer.argocd.argoproj.io/foreground  # <- # Cascade-delete managed resources when the Application is deleted (otherwise only the Application CR is removed).

spec:
  project: default
  source:
    repoURL: registry.odigos.io/charts
    chart: odigos
    targetRevision:  # REQUIRED: set the chart version from Step 2
    helm:
      releaseName: odigos
      values: |
        # OPTIONAL: add your custom Helm values here if needed.
        # Argo CD expects this field to be a YAML-formatted string.
        # To use chart defaults, delete this field entirely or set it to an empty string ("").
  destination:
    server: https://kubernetes.default.svc
    namespace: <ODIGOS_NAMESPACE>  # <- Replace with the desired namespace where you want Odigos to be installed
  # Chart regenerates odigos-deployment-id on every Argo render; ignore it to avoid OutOfSync flaps.
  ignoreDifferences:
    - kind: ConfigMap
      name: odigos-deployment
      jsonPointers:
        - /data/odigos-deployment-id
  syncPolicy:
    automated:
      prune: true
      selfHeal: true
    syncOptions:
      - CreateNamespace=true
      # Without this, sync still overwrites ignored fields from the rendered manifest.
      - RespectIgnoreDifferences=true
```

## Step 4: Apply the Application

Use `kubectl` to create the application in Argo CD:

```bash
kubectl apply -f odigos-application.yaml
```

This will instruct Argo CD to deploy Odigos using the Helm chart.

## Step 5: Monitor the Deployment

You can monitor the status of the deployment through the Argo CD UI:

* Navigate to your Argo CD web interface.
* Find the application named `odigos`.
* Verify that it reaches a **Healthy** and **Synced** state.

Once complete, Odigos will be installed in your cluster and ready to instrument workloads.
