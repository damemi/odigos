The **Network Metrics** rule enables network flow metrics and TCP stats metrics for instrumented workloads. These metrics are collected in odiglet and exported over OTLP alongside other workload telemetry.

Learn more about the underlying collectors and metric families in the [OBI instrumentation guide](/oss/instrumentations/obi).

## Considerations

<Warning>
  Before enabling **network metrics**, please note the following:
  - Network flow collection requires odiglet to run with `hostNetwork`. Enable the cluster infrastructure in Helm by setting `metricsSources.networkMetrics.disabled` to `false` (it defaults to `true`).
  - Network metrics apply to processes on a node that Odigos has successfully instrumented. The workload must have agent injection enabled.
  - Network metrics add eBPF overhead on host interfaces. Scope rules to specific workloads when possible.
</Warning>

<Note>
  TCP stats metrics are enabled together with network flow metrics when this rule is enabled. Stats metrics do not require `hostNetwork`, but network flow metrics do.
</Note>

<Info>
  Create `InstrumentationRule` resources in the Odigos installation namespace (typically `odigos-system`). Rules in other namespaces are not picked up by Odigos.
</Info>

## Configuration Options

<AccordionGroup>
  <Accordion title="networkMetrics">
    **networkMetrics** `object` : Enable network flow and TCP stats metrics for scoped workloads.
    - This field is *optional*
    <AccordionGroup>
      <Accordion title="enabled">
        **enabled** `boolean` : When `true`, network flow and TCP stats metrics collection is enabled for matching instrumented processes.
        - This field is *required* when `networkMetrics` is set
      </Accordion>
    </AccordionGroup>
  </Accordion>
</AccordionGroup>

<Note>
  Multiple rules merge with OR semantics: if any matching rule enables network metrics, they are enabled for that workload.
</Note>

## Cluster infrastructure for network flow metrics

Network flow metrics require odiglet `hostNetwork`. Configure this once at the cluster level in Helm:

```yaml
metricsSources:
  networkMetrics:
    disabled: false
```

The InstrumentationRule alone is not enough for network flow metrics without that Helm setting.

## Basic Example

The following example enables network metrics cluster-wide for all instrumented workloads.

<Steps>
  <Step title="Enable network metrics infrastructure">
    Set `metricsSources.networkMetrics.disabled` to `false` in your Odigos Helm values and upgrade the release.
  </Step>
  <Step title="Create the InstrumentationRule">
    Create a YAML file with the following content:

    ```yaml network-metrics.yaml
    apiVersion: odigos.io/v1alpha1
    kind: InstrumentationRule
    metadata:
      name: network-metrics
      namespace: odigos-system
    spec:
      ruleName: "Network metrics"
      networkMetrics:
        enabled: true
    ```
  </Step>
  <Step title="Apply the rule">
    ```shell
    kubectl apply -f network-metrics.yaml
    ```
  </Step>
  <Step title="Verify the rule merged into InstrumentationConfig">
    After the instrumentor reconciles, matching workloads should show `networkMetrics` enabled under `spec.containers[].metrics`:

    ```shell
    kubectl get instrumentationconfig -A
    kubectl get instrumentationconfig <workload-ic-name> -n <namespace> -o yaml | grep -A10 'metrics:'
    ```

    If pods were running before the rule was applied, restart them so odiglet re-attaches metrics collection for their processes.
  </Step>
</Steps>

## Scoped Example

To limit the rule to a single workload, add `scopes`. Omit `scopes` (or leave it empty) to apply the rule cluster-wide.

```yaml network-metrics-scoped.yaml
apiVersion: odigos.io/v1alpha1
kind: InstrumentationRule
metadata:
  name: network-metrics-my-app
  namespace: odigos-system
spec:
  ruleName: "Network metrics for my-app"
  scopes:
    sources:
      - name: my-app
        namespace: default
        kind: Deployment
  networkMetrics:
    enabled: true
```

Apply with:

```shell
kubectl apply -f network-metrics-scoped.yaml
```
