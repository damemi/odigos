# Odigos Enterprise Auth Extension

Gates the enterprise collector on a valid Odigos on-prem token.

| Status | |
| --- | --- |
| Stability | development |
| Distributions | `odigos-enterprise-collector` only |

## Why an extension

Every other enterprise component — odiglet, instrumentor, ui, central-backend, central-proxy —
calls `odigosauth.AssertEnterpriseOdigosToken` from its own `main()`. The collector can't: its
`main` is generated by the OpenTelemetry Collector Builder from `builder-config.yaml` and is
overwritten on every regeneration.

An extension is the supported way to run code across the collector's whole lifecycle, so that's
the mechanism used here.

## Behavior

- **At startup**, reads `ODIGOS_ONPREM_TOKEN` and verifies it with `odigosauth.VerifyOnpremToken`
  (RSA-signed JWT, checked against the public key baked into `odigosauth`). A missing, malformed,
  or expired token returns an error from `Start`, which aborts collector startup — the
  extension-level equivalent of the `os.Exit(1)` the other components perform.
- **While running**, watches `odigosauth.TokenExpirationChannel`. If a token that was valid at
  startup later expires, the extension reports a fatal error so the collector shuts down through
  its normal path rather than calling `os.Exit` from a library goroutine.

## Configuration

None. The token comes from the `ODIGOS_ONPREM_TOKEN` environment variable, which Helm populates
from the `odigos-pro` secret exactly as it does for odiglet, instrumentor, and ui. There is nothing
an operator could set here that isn't already governed by whether that secret exists.

```yaml
extensions:
  odigos_enterprise_auth:

service:
  extensions: [odigos_enterprise_auth, health_check, pprof]
```

## Note on image pull authentication

This extension covers **runtime** token verification. Authenticating the *image pull* against
`registry.odigos.io` is separate and already handled: the `odigos-enterprise-registry` pull secret
is registry-wide, reaching the node collector through the odiglet DaemonSet's `imagePullSecrets`
and the cluster collector through `odigos-configuration`.
